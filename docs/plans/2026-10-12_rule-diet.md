# Rule diet — what loads every session, and what it should be

2026-10-12. A proposal; nothing below has been executed. Measured in `~/Research/NAR_settlement`.

## What actually loads at session start

The 2,600-line figure is the whole `rules/` tree. Most of it (`quarto-empirical.md`,
`permissions.md`, `lifecycle.md` and ten others, ~2,100 lines) is in `claudeMdExcludes` and loads
only when a skill or agent reads it. What every session carries is about **1,050 lines / 66 KB
(~16k tokens)**, plus the superpowers plugin's session-start injection and roughly 90 skill
descriptions:

| Always loaded | Lines | Mostly |
|---|---|---|
| `~/.claude/CLAUDE.md` | 141 | real rules, each with rationale and sub-rules |
| `~/Research/CLAUDE.md` | 74 | real rules |
| `rules/agents.md` | 156 | dispatch mechanics, enforcement narrative, incident history |
| `rules/content-invariants.md` | 150 | critic checklist + enforcement table |
| `rules/shared-pipeline.md` | 78 | symlink mechanics |
| `rules/meta-governance.md` | 59 | `/promote` and ledger procedure |
| `rules/systematic-debugging.md` | 58 | duplicated by superpowers' own skill |
| `rules/literature-search-order.md` | 10 | real rule |
| `NAR_settlement/CLAUDE.md` | 301 | dated status history, much of it marked superseded |

Three problems, in order of cost:

1. **The project CLAUDE.md contradicts itself.** NAR's file says treatment is dated by contract
   from 2024-08-15 (line 11) and that the treatment date is October 1, 2024 (line 251); names the
   manuscript as `manuscript_NAR_denver.qmd` (line 3) and as `manuscript_NAR_settlement.qmd`
   (line 118); says the paper tests H1–H4 (line 27) and lists H1–H3 (lines 172–175). Line 31 says
   "everything below this line is history", above sections that are still live conventions. A
   session that trusts what it was told at start-up asserts the stale version. This is the
   cheapest failure to remove and probably the one that cost the most.
2. **Mechanics crowd out rules.** Roughly two thirds of the loaded pipeline text is how the
   pipeline is enforced, why, and what went wrong once. That belongs to the skills and docs that
   use it. The rules a session most needs (one manuscript, explorations, read before editing)
   were in an excluded file.
3. **Competing instruction sets.** superpowers injects an "EXTREMELY_IMPORTANT … you do not have a
   choice" block every session and ships its own brainstorming, debugging, TDD and plan
   workflows that overlap the pipeline's. Everything shouting priority means nothing has it.

## Target: about 150 lines always loaded

**Tier 1 — always loaded (target ≤ 150 lines in total).**
- `~/.claude/CLAUDE.md` → ~50 lines. Keep every rule; drop the sub-numbering and rationale (it is
  already in `rule-history.md`). Read-before-asserting becomes 3 lines (the hooks carry the rest);
  chat output 3 lines; R naming 2 lines plus the grep.
- `~/Research/CLAUDE.md` → ~40 lines, largely as is.
- **New `rules/core.md` (~30 lines)** replaces the six loaded pipeline files: one manuscript;
  `explorations/` for model tests; `scripts/acquire/` for acquisition; every prose number inline
  (INV-11); exhibits and references from the renderer (INV-13/25); every creator gets its registry
  critic, dispatched in the foreground; critics never edit; never edit the shared `.claude/` tree
  without asking; local Zotero before the web; two failed fixes → stop and report. Each line names
  the hook or script that enforces it, or says `judgment`.
- **Project `CLAUDE.md` ≤ 40 lines:** title, `manuscript:`, target journal and deadline, the
  current status in three lines, the one gate command, data locations, and pointers
  (`HANDOFF.md`, `model_corrections.md`). Dated status history moves to `docs/status_history.md`.
  A cap enforced by `check_install.sh` keeps it from growing back.

**Tier 2 — loaded on demand.** `agents.md`, `content-invariants.md`, `shared-pipeline.md`,
`meta-governance.md` and `systematic-debugging.md` join the excluded set. The skills and agents
that need them already name them (`/pipeline`, the critics, `/promote`, coder, data-engineer).
This step needs a reference check per file before it lands.

**Tier 3 — enforced, not written.** Rules a hook or script enforces get one line in `core.md`
and no prose. Live now: `script-guard.py`, `read-gate.py`, `prose_number_check.py`,
`quarto_structure_check.py`, `pipeline.py post`. Candidates: the R-naming grep as a PostToolUse
lint; quiet the global grep reminder so it fires only on partial reads.

**Tier 4 — never loaded.** Incident histories and "why" go to `docs/` and `rule-history.md`.

## Execution, once approved

1. NAR `CLAUDE.md` → ≤ 40 lines, history moved out (project commit). Same pass for POGM4 and the
   others after measuring them.
2. Write `rules/core.md`; move the five files to `claudeMdExcludes`; check every reference to
   them resolves from the skill or agent that needs it; land through `/promote`.
3. Trim `~/.claude/CLAUDE.md` with the history already in `rule-history.md`.
4. superpowers off in `~/Research` sessions (project-level `enabledPlugins` — unverified that a
   project setting can override a user-level enable; test before relying on it).
5. Measure: run a session in NAR, compare `/context` before and after, and check transcripts for
   script-guard and read-gate denials over the following week.
