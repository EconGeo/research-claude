## Vacuous reds

- **`pre-writer-red`** (`expect_fail pre-writer-red python3 "$RC/scripts/pipeline.py" --root "$T"
  pre writer`) reports `PASS`, but this is a **fake green**, not a real one. `expect_fail` only
  asserts that the command exits non-zero — and it does, because `scripts/pipeline.py` does not
  exist at all, so `python3` fails with "can't open file" before any argument parsing, gate
  logic, or coder-critic-score check ever runs. The check has never exercised the actual
  predicate it is named for ("no coder-critic score yet blocks the writer stage"); it would
  report the identical `PASS` for any reason `pipeline.py` fails to run — a syntax error, a
  missing import, wrong permissions, anything.
- This green carries **no information** about whether the pre-writer gate logic is correct, or
  even exists. It must not be cited as evidence that gate is enforced.
- **Task 1.7**, which writes `scripts/pipeline.py`, must supply its own genuine red for this
  check before its later green can be trusted: run `pipeline.py --root "$T" pre writer` against
  a fixture state that has *not yet* accumulated a passing coder-critic score and confirm it
  fails for that reason (not "file not found"), then confirm it starts passing only once the
  score is present. Until that genuine red is recorded, a green `pre-writer-red` in this harness
  proves nothing beyond "the script exists and ran."
- **`[pipeline.py]` in `scripts/check_fork.sh`** (`── registry (scripts/pipeline.py registry
  check) ──` → `FAIL [pipeline.py] scripts/pipeline.py absent`, see `## check_fork.sh` below) is
  the mirror case: a **vacuous red**, not a genuine one. The criterion only tests that the file
  exists at all — it never reaches whatever registry-state logic `pipeline.py` is meant to
  enforce, because there is no script to run that logic. It would report the identical FAIL for
  any reason short of the file's mere presence (a stub with no registry check, a script that
  always exits 0 once it exists, anything).
- This red carries **no information** about whether the registry-check logic is correct, or even
  written yet. It must not be cited as evidence that the registry gate is enforced.
- **Task 1.7**, which writes `scripts/pipeline.py`, must supply its own genuine red for this
  criterion too: get `check_fork.sh`'s `[pipeline.py]` check past "script absent" and show it
